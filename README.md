# Fleet Analytics

Organization-level analytics dashboard for **Fleet**, an imaginary platform where engineers delegate coding tasks to agents that run in isolated cloud sandboxes and open pull requests. A take-home assignment for a developer-tools company, built spec-first with an AI-first workflow.

> **Status: day 0.** Specifications in progress, no code yet. This README grows with the repo; the git log is the build diary.

## What this is

A customer-facing dashboard that lets an engineering organization understand its use of cloud coding agents — adoption, outcomes, quality, cost, reliability and governance — at the org and team level, not the individual engineer.

## How it's being built

Spec-driven, in this order, one commit per document so the history shows each decision as it was made:

1. Research & product framing — personas, the one question the dashboard answers, which metrics earn a place
2. Architecture — the production design, and the boundary between what the prototype implements and what it mocks
3. Requirements — user stories with acceptance criteria
4. Technical spec — stack, structure, normative metric definitions, API contracts
5. Testing spec — how every acceptance criterion is proven
6. Plan — milestones and the cut line
7. AI workflow — how Claude Code was driven, and where it was wrong
8. Decision records (ADRs)

Then implementation: one milestone per pull request, tests first.
